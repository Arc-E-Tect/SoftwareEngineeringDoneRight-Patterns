:icons: font

[NOTE]

The Domain Validation API exposes business-rule validations from the bounded context that owns the rules.
Each bounded context offers its validations as typed operations in its own API, following one shared set of conventions for the contract, the outcome and asynchronous execution.

link:domain-validation-api-pattern.adoc[The pattern document →] describes the pattern in full: its context, problem and forces, the solution, the implementation in Spring Boot following Hexagonal Architecture, its consequences, variants and rejected alternatives.

== Reference implementation

The reference implementation is the payments bounded context with one validation, `name-iban-match`: does the name the payer provides match the name of the holder of the account with the given IBAN?

== The document and the implementation

The pattern document is the specification, and the reference implementation follows it.
Where building the implementation leads to a decision that changes the pattern, the document is changed with it, and link:../../docs/decision-log.adoc[the decision log →] records the decision and its reason.
